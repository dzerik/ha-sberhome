# scenario-schedules Specification

## Purpose
Сохранять TIME-условия без потерь и разрешать изменение простых расписаний
без сброса даты начала, часового пояса и остальных условий сценария.

## Requirements

### Requirement: Сохранность исходного TIME

Редактор SHALL сохранять исходное TIME-условие, включая неизвестные поля,
когда пользователь меняет другие части сценария.

#### Scenario: Изменение имени
- **GIVEN** сценарий содержит TIME с execute_at или неизвестными полями
- **WHEN** пользователь меняет только имя и сохраняет сценарий
- **THEN** исходное TIME-условие передаётся без потери полей и значений

#### Scenario: Неизвестная форма
- **GIVEN** TIME содержит отсутствующий или null rrule либо непривычный time_data
- **WHEN** пользователь меняет другое действие
- **THEN** TIME сохраняется целиком с исходными типами и различием missing/null
- **AND** TIME внутри неподдерживаемой группы сохраняется вместе со всей веткой

### Requirement: Честное представление поддерживаемого подмножества

Простой редактор SHALL разрешать правку расписания только если способен
сохранить все значимые параметры его формы. Другие TIME SHALL отображаться
без выдачи их за простой ежедневный график и сохраняться без преобразования.

#### Scenario: Ограниченное или сложное правило
- **GIVEN** RRULE содержит неподдерживаемые COUNT, UNTIL, INTERVAL или несколько времён
- **WHEN** пользователь открывает сценарий
- **THEN** расписание доступно для чтения без упрощения в DAILY
- **AND** правка несвязанного действия не удаляет ограничения RRULE

### Requirement: Сохранение якоря и часового пояса

Изменение дней или времени поддерживаемого расписания SHALL сохранять
его DTSTART и timezone, если пользователь явно не изменяет их.

#### Scenario: Правка минут
- **GIVEN** поддерживаемое расписание имеет заданный DTSTART и TZID
- **WHEN** пользователь меняет минуты
- **THEN** DTSTART и TZID сохраняются
- **AND** изменяется только выбранное время расписания

### Requirement: Непустой выбор дней

Редактор SHALL блокировать сохранение поддерживаемого расписания без
выбранных дней вместо молчаливой подстановки всех дней недели.

#### Scenario: Снят последний день
- **WHEN** пользователь снимает последний выбранный день
- **THEN** редактор сообщает о незавершённом вводе
- **AND** не превращает его в ежедневное расписание

#### Scenario: Пустое время или неверная зона
- **GIVEN** пользователь создаёт либо редактирует расписание простым редактором
- **WHEN** время очищено либо timezone не распознаётся
- **THEN** сохранение блокируется с понятной ошибкой
- **AND** редактор не подставляет 00:00 или фиксированную дату вместо исходного значения

### Requirement: Адресное удаление расписания

Удаление выбранного TIME SHALL сохранять остальные триггеры, действия,
идентификатор, timezone и активность сценария. Ошибка облака SHALL быть
показана пользователю без ложного подтверждения сохранения.

#### Scenario: TIME и голосовая фраза
- **GIVEN** сценарий содержит TIME и PHRASES
- **WHEN** пользователь удаляет только TIME и облако подтверждает изменение
- **THEN** PHRASES, действия и идентификатор сохраняются
- **AND** расписание отсутствует при последующей перечитке
- **AND** удалённое расписание больше не вызывает запуск в прежний срок

#### Scenario: Два расписания
- **GIVEN** сценарий содержит TIME для A и TIME для B
- **WHEN** пользователь удаляет только TIME для A
- **THEN** запуск в A отсутствует, а расписание B сохраняется
- **AND** активность сценария не выключается вместо удаления TIME

#### Scenario: Перенос A на B
- **WHEN** пользователь меняет поддерживаемое расписание с A на B
- **THEN** прежний запуск A отсутствует и сценарий запускается в B
- **AND** остальные условия и действия сохраняются

#### Scenario: Ошибка облака
- **WHEN** облако отклоняет изменение расписания
- **THEN** редактор сообщает об ошибке
- **AND** не выдаёт прежнее расписание за успешно изменённое или удалённое

### Requirement: Последний триггер

Клиент SHALL блокировать сохранение draft без PHRASES и без триггеров до
обращения к облаку и предлагать добавить условие или выключить автосрабатывание.

#### Scenario: Удаление единственного TIME
- **GIVEN** у сценария нет PHRASES и есть единственный TIME
- **WHEN** пользователь удаляет этот TIME
- **THEN** сохранение блокируется с понятным объяснением
- **AND** UI и backend валидация не отправляют пустой CONDITIONS в облако
