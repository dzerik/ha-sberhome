# Proposal

## Why

[#80](https://github.com/dzerik/ha-sberhome/issues/80): после верного SMS-кода
Сбер иногда требует email-подтверждение. Сейчас `verify_otp` ожидает финальный
authcode и считает ответ с `email_otp` ошибкой, а config flow повторно предлагает
SMS. Пользователь с дополнительным фактором не может завершить вход.

## What Changes

- Представить промежуточный challenge как продолжение авторизации.
- После SMS показывать отдельный шаг email-кода, если его потребовал сервер.
- Дождаться финального authcode до обмена на токены и проверки Smart Home.
- Сохранить вход только по SMS, повтор проверки облака и reauth.
- Добавить переводы и исключить коды/контекст challenge из журналов ошибок.

Вне объёма: исправление браузерного редиректа из №78, новые виды факторов,
автоматический доступ к почте и изменения общего менеджера refresh-токенов.

## Capabilities

### New Capabilities

- `csafront-email-otp`: продолжение встроенной авторизации через email-код.

### Modified Capabilities

Нет: существующий контракт порядка действий сценариев не изменяется.

## Impact

`aiosber/auth/csafront.py`, `config_flow.py`, локализация форм, тесты клиента и
config flow. Формат initialize/verify подтверждён публичным официальным клиентом
провайдера (см. protocol.md). Реальный вход аккаунтом с email-фактором ещё
требует проверки; реализация поставляется в тестовой версии 6.3.1b1.
