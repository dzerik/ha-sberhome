# Проверка №80

Версия: **6.3.1b1**, 2026-11-04. Требования реализованы, проверка живого
SMS→email входа остаётся открытой (нет соответствующего аккаунта).

## Источник и воспроизведение

Тест ответа из №80 до исправления падал с AuthError вместо перехода к email:
`pytest --no-cov tests/aiosber/auth/test_csafront.py -k verify_sms_returns_email`.
Формат запросов подтверждён официальным клиентом Sber ID r-97.0.0,
см. [protocol.md](protocol.md). Запросы отправки кодов реальным аккаунтам
в ходе исследования не выполнялись.

## Проверки

- Полный `.venv/bin/pytest -q`: **2900 passed**, 5 warnings, 53.43 s;
  покрытие **99.16%**, порог 99% пройден.
- Ruff check/format: успешно, 352 файла.
- mypy: ошибок нет, 171 исходный файл; список исключений не расширялся.
- `git diff --check`: успешно.

Тесты проходят через реальный менеджер config flow HA и настоящий клиент;
облако подменено на уровне httpx. Проверяются SMS-only, SMS→email, уже
инициализированный email, новый ouid, cookies в одном HTTP-клиенте, неправильный
и пустой код, повторная отправка письма, сбой инициализации, неизвестный фактор,
истёкшая сессия, повтор только Smart Home probe, reauth того же аккаунта и
закрытие HTTP-клиента при отмене. На всех стадиях проверяется отсутствие
содержимого сырых ответов в сообщениях ошибок.

Переводы формы и ошибок присутствуют в strings.json и во всех пяти локалях.
Наличие пояснения у каждого поля проверяется существующим контрактным тестом.

## Ограничение

Успешный мок-тест подтверждает реализацию принятого контракта, но не работу
email-фактора на реальном аккаунте. До этой проверки задача 3.1 не отмечается
выполненной, изменение не архивируется и issue №80 не закрывается.
