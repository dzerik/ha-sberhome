# Design

## Context

Корневой panel импортирует modal с ?v=<release>, но modal раньше статически
импортировал ../i18n/index.js, а тот — ./dicts.js. URL зависимостей оставались
постоянными. Node-тест с уже загруженным старым i18n воспроизводит точный
симптом: ru: stale translation regime_title. HTTP GET с HA подтвердил
соответствие файлов локальным, наличие новых переводов и отсутствие Cache-Control.
Это исключает неполный деплой и подтверждает необходимость обновления URL
зависимостей независимо от версии родительского модуля.

## Decisions

- Использовать уже существующий query v модалки для динамического импорта Localized.
- i18n/index.js передаёт собственный v импорту DICTS. Обе зависимости получают
  новый URL при обновлении; ESM-кэш прежней версии не подменяет новый словарь.
- При отсутствии v сохранять прежние URL. Имена экспортов и синхронный интерфейс
  localize/Localized не меняются; top-level await уже используется панелью.
- Не очищать кэш браузера программно и не менять данные сценариев.

## Validation

Постоянный Node-тест сначала вычисляет старый unversioned i18n без ключей
regime/period, затем обновляет файлы и импортирует настоящий modal с новой
версией. До исправления assert получает ключ вместо перевода; после проходят
все пять локалей и summary трёх команд.

Headless Chrome получает старый unversioned словарь с долгим HTTP-кэшированием.
Проверяются реальные versioned запросы index.js и dicts.js, подписи в DOM,
пять локалей, отсутствие ошибок JS и скриншоты desktop/mobile.
Затем pytest, Ruff, mypy, OpenSpec и деплой через SSH/tar.gz с перезапуском HA.
