# Проверка REGIME_COMMAND — часть №68

Дата: 2026-11-04. Версия: 6.4.0b3.

## Контракт и регрессии

Исходные тесты показали 12 отказов: блок оставался unknown, новый action
терялся при encode, некорректный список не отклонялся. После реализации
поддерживаются HEAD_DIALOG_COMMAND с morning/evening/night, обычными
calendar/daypart и пустым rrule. Другие варианты целиком остаются raw/read-only.

Тесты проверяют точный round-trip наблюдаемого блока, сохранность оболочки,
Id и задержек каждой вложенной задачи, удаление средней команды, запрет повторения
периода, новые строки, неизвестные/некорректные формы и отсутствие мутаций.
Обнуление общей задержки отдельно проверено при ненулевой задержке в raw.

Настоящий путь WS → IntentService → encoder → подменённый cloud transport →
decoder проверен на полной фикстуре: меняется текст и удаляется команда,
соседние действия и вложенные неизвестные условия остаются без изменений.
Node-тест запускает реальные обработчики формы, включая запрет неполного
сохранения, read-only, неизменность исходного intent и отправляемый WS payload.

## Браузер

Настоящий Lit-компонент в headless Chrome, backend подменён тестовым
hass.callWS. Проверены реальные события выбора периода/колонки и ввода текста,
удаление и добавление строк, отсутствие наследования Id/задержек новой строкой,
валидация, пять локалей и disabled у вложенных полей read-only сценария.
Занятые периоды отключены в select; кнопка добавления недоступна при трёх

## Локальный деплой и облако

Пакет передан через SSH/tar.gz. До замены сверены SHA-256 всех 217 файлов
с предыдущей установленной 6.3.1b1: изменений на HA не было.
Проверка конфигурации после замены прошла. Резервный архив:
`/config/.sberhome-deploy/20261104T105015Z/sberhome-before.tar.gz`.

Первая live-попытка без условий отвергнута: HTTP 500, code 2,
`bad nested condition`. Для отдельного теста используется уникальная служебная
фраза, без расписаний и условий по устройствам.

Создание с is_active=false в 6.4.0b1 вернуло активный сценарий. Проверка
остановилась, созданный ID удалён; run не вызывался. Это потребовало исправления
IntentService: отключение после POST/PUT подтверждается PATCH /active,
при отказе отключения новый ID удаляется. До исправления пять новых сервисных
регрессий падали, после — проходят. Проверяются POST/PUT с обоими вариантами
is_active в ответе и удаление после ошибки PATCH.

В 6.4.0b2 отдельный GET подтвердил отключённое состояние после PATCH.
Следующая проверка выявила нормализацию REGIME_COMMAND: при отправке двух
команд evening облако сохранило только последнюю, а порядок уникальных
периодов в ответе отличался от запроса. Временные сценарии удалены.

Поэтому 6.4.0b3 запрещает повторяющиеся периоды до HTTP, не предлагает занятые
периоды в форме и ограничивает список тремя командами. Наблюдаемые дубликаты
при decode остаются неизвестным read-only блоком. Порядок строк в ответе
облака не является пользовательским контрактом; metadata сопоставляются
с собственной командой, а не индексом строки ответа.
