# Spec Delta

## Purpose

Позволить редактировать команды ассистенту по периодам суток внутри облачного
сценария, сохраняя ограничения и данные его остальных действий и условий.

## ADDED Requirements

### Requirement: Редактирование команд по периодам

Редактор SHALL показывать поддерживаемый список команд по периодам как
редактируемое действие с периодом, колонкой и текстом каждой команды.

#### Scenario: Открытие поддерживаемого блока
- **GIVEN** сценарий содержит команды для morning, evening и night
- **WHEN** пользователь открывает редактор
- **THEN** видны три строки с соответствующими периодами, колонками и текстами
- **AND** этот блок сам по себе не переводит сценарий в read-only

#### Scenario: Изменение списка
- **WHEN** пользователь меняет текст, колонку или период, добавляет либо удаляет строку и сохраняет
- **THEN** после повторного открытия отображаются выбранные значения; порядок строк может нормализоваться облаком

### Requirement: Проверка обязательных полей

Система SHALL отклонять сохранение редактируемого блока без команд,
без колонки или непустого текста, с неподдерживаемым либо повторяющимся периодом.

#### Scenario: Некорректная команда
- **WHEN** в отправленном редактируемом блоке отсутствует колонка или текст
- **THEN** сохранение завершается понятной ошибкой до записи в облако
- **AND** исходный сценарий остаётся без изменений

#### Scenario: Повторяющийся период
- **WHEN** две строки редактируемого блока содержат один период
- **THEN** сохранение отклоняется до HTTP-запроса
- **AND** облако не получает список, в котором молча заменило бы первую команду последней

### Requirement: Сохранность существующих данных

Система SHALL сохранять служебные поля и задержки каждой существующей команды,
данные оболочки блока, соседние действия и неизвестные условия при редактировании.

#### Scenario: Удаление средней строки
- **GIVEN** команды A, B, C имеют разные служебные поля и задержки
- **WHEN** пользователь удаляет B
- **THEN** исходящий payload сохраняет собственные поля, задержки и взаимный порядок A и C
- **AND** порядок периодов в ответе может нормализоваться облаком

#### Scenario: Неизвестные условия
- **GIVEN** у сценария есть вложенное read-only условие
- **WHEN** пользователь изменяет текст команды по периоду
- **THEN** данные и логика вложенного условия сохраняются

### Requirement: Неизвестные варианты остаются read-only

Система SHALL оставлять неподдерживаемый вложенный тип, период или календарное
ограничение недоступными для редактирования с сохранением исходного payload.

#### Scenario: Неизвестная вложенная задача
- **WHEN** блок содержит задачу неизвестного типа
- **THEN** весь блок остаётся read-only
- **AND** допустимое сохранение имени сценария не меняет этот блок


### Requirement: Сохранение отключённого сценария

Система SHALL подтверждать отключение через dedicated active endpoint после
создания или сохранения отключённого сценария, поскольку облако может
игнорировать is_active=false в POST/PUT.

#### Scenario: Облако создаёт активный сценарий
- **GIVEN** пользователь создаёт отключённый сценарий
- **WHEN** облако отвечает на POST активным сценарием
- **THEN** сервис отключает созданный ID отдельным PATCH /active
- **AND** возвращает отключённое состояние только после успешного PATCH

#### Scenario: Не удалось отключить новый сценарий
- **WHEN** PATCH отключения после создания завершается ошибкой
- **THEN** сервис удаляет только что созданный сценарий
- **AND** сообщает об ошибке вместо успешного создания
