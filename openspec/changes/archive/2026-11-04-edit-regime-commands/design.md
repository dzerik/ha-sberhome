# Design

## Context

`tests/intents/fixtures/scenario_full_example.json` и read-only запрос к
`sberhome/intents/list` подтверждают один REGIME_COMMAND с массивом
`regime_command_data.tasks`. Каждый вложенный HEAD_DIALOG_COMMAND содержит
`head_dialog_command_task_data.device_id/text` и `regime_condition.period`.
Наблюдались morning/evening/night, daypart/calendar=common, пустой rrule.
Запись сценария уже реализована через PUT `/scenario/v2/scenario/{id}`.

## Decisions

1. Новый action type `regime_command` содержит список `commands` с полями
   period/device_id/text. Исходная оболочка и каждая вложенная задача хранятся
   в отдельных `_raw` копиях; удаление строки не переносит Id/задержку соседней.
2. Decoder принимает только полностью поддерживаемый блок. Если вложенный тип,
   период или календарное ограничение неизвестны либо период повторяется, весь блок остаётся unknown.
3. Encoder обновляет редактируемые поля в глубоких копиях raw. Новые команды
   получают common daypart/calendar, пустой rrule и start_delay=0s. Задержки
   существующих вложенных задач остаются без изменения. Некорректный список
   вызывает ошибку до HTTP-запроса, а не превращается в пустые tasks.
4. UI использует schema field type `regime_commands` и существующий picker
   колонок. Каждая строка редактирует период/колонку/текст; список допускает
   только одну команду каждого периода, максимум три. Минимум — одна команда.
   Live PUT подтвердил: облако молча заменяет дубликаты последним значением,
   поэтому UI и encoder отклоняют повторения. Порядок строк может меняться
   сервером; сопоставление служебных полей не опирается на индекс ответа.
5. Вложенные CONDITIONS сохраняются как raw read-only. Пользовательский
   сценарий используется только для чтения; live CRUD выполняется отдельно
   на отключённом тестовом сценарии с уникальной служебной фразой, без расписаний.
   Live create без условий отвергнут облаком как bad nested condition; is_active=false
   в POST проигнорирован. IntentService подтверждает отключение через PATCH /active
   после POST/PUT, при неудаче отключения нового сценария удаляет его.

## Validation

Тесты реестра и полного encoder round-trip: фикстура, metadata/Id/задержки,
порядок encoder, запрет одинаковых периодов, новые/удалённые строки, неизвестные варианты и
отсутствие мутаций. Поведенческий Node-тест настоящих методов формы и
браузерная проверка рендера/валидации/локализации. Затем полный pytest,
Ruff, mypy и OpenSpec validate. Деплой на локальный HA через SSH/tar.gz.

На временном отключённом сценарии проверить create/get/update/get/delete
без запуска. Зафиксировать фактическую нормализацию сервером; завершить
проверку удалением только созданного тестового ID.
