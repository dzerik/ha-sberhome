# Design

## Context

В `www/components/sberhome-intent-modal.js` действия находятся в `_draft.actions`;
`_editingActionIdx` выбирает открытый визард. `_onRemoveAction` уже корректирует
индекс после удаления. В `_renderActionDigest` есть удаление, перемещения нет.

`intents/encoder.py:encode_scenario` проходит actions по порядку, но
`_decode_tasks` перебирает регистрации типов и извлекает совпадения из всего
списка. Поэтому разные типы группируются в порядке реестра, unknown попадают
в конец. Это подтверждено локальным вызовом публичных decode/encode для одного
step с командой лампе и TTS: порядок после round-trip обратился.

## Goals / Non-Goals

Сохранить порядок поддерживаемого списка задач и добавить доступное с клавиатуры
перемещение. Сохранить задержки, read-only ограничения и выбор визарда.
Многосоставные steps и новые типы действий остаются за границами изменения.

## Decisions

1. Использовать две кнопки перемещения на одну соседнюю позицию; на границах
   соответствующая кнопка отключена. Подписи/aria-label берутся из i18n панели.
2. Переставлять объекты целиком в новом массиве; исходный `intent` не мутировать.
   При пересечении выбранного действия корректировать `_editingActionIdx`.
3. Декодировать задачи в исходной последовательности. Для текущих регистраций
   проверить, сколько wire-tasks потребляет один decoder, и сохранить это
   соответствие; unknown занимает исходное место. Публичный интерфейс реестра
   менять только при доказанной необходимости.
4. Существующее read-only поведение Sber-managed сценариев сохраняется:
   неизвестные блоки не становятся редактируемыми из-за появления reorder.

## Risks / Trade-offs

- Группировка decoder'ом нескольких tasks требует явного теста границ группы;
  восстановление позиции через сравнение словарей опасно при одинаковых tasks.
- Нужны тесты чередования типов, повторяющихся действий и unknown между ними.
- Перемещение неизвестных блоков в UI не входит в объём, но их позиция при
  round-trip является контрактом сохранности данных.

## Validation

Поведенческий тест JS через существующий Python/Node подход из
`tests/test_www_frontend.py`: реальные методы компонента, перестановка,
границы, выбранный визард и неизменность исходного массива. Проверка encoder
через `tests/intents/test_encoder.py`: разные типы, одинаковые задачи,
unknown и задержки. Проверка WS save/load — `tests/intents/test_websocket.py`.
Затем обязательные проверки репозитория и скриншоты изменений панели.

## Open Questions

Протокольных блокеров для текущих поддерживаемых action types не выявлено.
Несколько cloud steps требуют отдельного решения; этот change их не объединяет
и не переопределяет сверх существующего поведения.

## Implementation

Все шесть встроенных типов с wire-задачами декодируют одну задачу в одно
действие; `ha_event_only` соответствует пустому списку. `_decode_tasks` теперь
передаёт одну задачу каждому decoder до первого совпадения, а задержку берёт
непосредственно из этой задачи. Интерфейс реестра сохранён.

Обработчик перемещения переставляет ссылки на объекты в копии массива и
корректирует индекс открытого визарда. Read-only и unknown защищены также
в обработчике. Кнопки локализованы существующим `Localized`-миксином.
Результаты проверки находятся в [validation.md](validation.md).
