# Design

## Context

SberAtHomeSwitch/SberScenarioActiveSwitch уже существуют. `_run_ws` подписан
на DEVICE_STATE/DEVMAN_EVENT/GROUP_STATE/SCENARIO_WIDGETS. HomeChangeVariableDto
имеет change_type/id/variable, но смысл id и полный variable-контракт не
подтверждены. `_on_ws_other_topic` лишь записывает это сообщение.
ScenarioAPI.stop/cancel существуют; реальный контракт необходимо проверить.

Актуальный main содержит принятый #76 — TLS WS через общий SSL-контекст.
Изменение строится поверх него и опубликованной базы 6.4.0b5 (PR #84).

## Decisions

- SCENARIO_HOME_CHANGE_VARIABLE сигнализирует перечитать состояния сценариев/присутствия.
  Не присваиваем bool из неполностью известного payload и не угадываем home_id.
- Отдельный отслеживаемый worker объединяет burst сообщений; сигнал во время
  GET вызывает повторную итерацию. Ошибка сохраняет polling fallback; shutdown
  отменяет worker. Перечитка уведомляет сущности существующим push-механизмом,
  который не сдвигает основной плановый опрос устройств.
- Run остаётся прежней сущностью с прежним unique_id. Две отдельные control
  entities вызывают coordinator → ScenarioAPI.stop/cancel и существующий перевод
  облачных ошибок. Они используют общий service-device сценариев.
- Обнаружение новых сценариев по обновлению coordinator добавляет три кнопки
  один раз; исчезнувший объект становится unavailable. Unique_id не меняются.
- Проверка WS: моки/реальный coordinator, подключение реального WS и read-only
  replay-сигнал с последующим GET. Изменение присутствия настоящего дома может
  запускать пользовательские автоматизации, поэтому такой live-toggle не делаем.
- Проверка stop/cancel: только отдельные временные сценарии. Если потребуется
  исполняющаяся задача, она может лишь менять активность другого тестового
  сценария с задержкой; физических устройств это не затрагивает. Cleanup обязателен.

## Validation

Регрессии до реализации, реальные HA entity/WS tests и burst/error/shutdown,
без повторной генерации сущностей и с сохранением идентификаторов. Полные pytest
≥99%, Ruff, mypy, OpenSpec, CI Python 3.13/3.14, SHA-проверка пакета.
SSH/tar.gz backup/check/restart. Live-контракт stop/cancel фиксируется отдельно;
HTTP success не приравнивается к доказательству остановки исполняющегося сценария.
PR → merge → tag → CI-gated prerelease; комментарий в №62 с границами проверки.


## Live Findings

6.4.0b6 подключилась к облачному WS, включая новую подписку. Read-only replay
домашней переменной перечитал API и обнаружил новый тестовый сценарий; режим
дома не менялся. Stop/cancel для idle-сценария принимаются.
Контрольная отложенная операция меняла только активность тестового target:
без stop она выполнилась, с stop — нет. Cancel во время выполнения вернул
409 not allowed; удаление выполняющегося теста тоже вернуло 409, после завершения
он удалён повторным запросом. Все тестовые сущности HA удалены.
Cancel проверяется отдельно перед будущим TIME, с параллельным положительным
контролем. Для running cancel добавлена отдельная переведённая подсказка Stop.
