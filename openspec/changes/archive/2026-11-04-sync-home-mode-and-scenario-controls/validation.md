# Проверка №62 — WS и stop/cancel

Дата: 2026-11-04. Версия: 6.4.0b6. База — опубликованная v6.4.0b5, PR #84.

## Реализация и тесты

Начальные пять тестов падали из-за отсутствующих control-entities и handler.
Кнопки запуска сохраняют прежний unique_id; stop/cancel получают отдельные ID,
переводимые имена и стандартную обработку ошибок HA. Discovery добавляет
новые сценарии один раз, удалённые становятся unavailable. На настоящем HA
проверены friendly_name пяти языков, сервис button.press, точный endpoint,
отсутствие run при control-вызовах и динамическая регистрация без дублей.

WS-подписка и TopicRouter маршрутизируют SCENARIO_HOME_CHANGE_VARIABLE
в coalesced перечитку API. Поля неизвестного payload не присваиваются состоянию.
Два дома проверены с противоречащим payload: используются значения GET каждого
дома. Burst во время первого запроса вызывает ровно одну дополнительную
итерацию; ошибку можно пережить и повторить, shutdown отменяет worker и
игнорирует запоздалые сигналы. Учтён eager task start HA: задача создаётся
с eager_start=False, чтобы мгновенное завершение не оставляло stale task slot.

Cancel во время выполнения отвечает 409 not allowed. Для него есть отдельная
ошибка с подсказкой Stop, переведённая на пять языков. Прочие ошибки проходят
прежний общий перевод. Подтверждение регистрации новых имён выполняется через
настоящий реестр HA, а не только чтение JSON переводов.

## Живой HA и облако

Первая сборка 6.4.0b6 установлена через SSH/tar.gz после SHA-проверки прежней
локальной 6.4.0b5. Config check прошёл; WS подключён с новой подпиской,
polling успешен, consecutive_failures=0.

Read-only replay домашней переменной вызвал перечитку, после которой появились
кнопки только что созданного тестового сценария. Значение реального «дома»
не менялось. Доставку внешнего at_home push от приложения намеренным
переключением настоящего дома не провоцировали, чтобы не запускать его автоматизации.

Все действия проверки управляли только активностью созданных тестовых
сценариев; команд устройствам и сообщений пользователям в них нет.

- Idle stop/cancel приняты API и выполнены через реальные HA-кнопки.
- Положительный контроль: отложенный SCENARIO_SET_ACTIVE активировал тестовую цель.
- Stop до истечения задержки предотвратил эту операцию.
- Cancel для уже выполняющегося сценария вернул 409; это отдельная семантика,
  не синоним Stop. Первый DELETE выполняющегося теста также вернул 409;
  повтор после завершения удалил его. Все его HA-сущности очищены.
- Первая сокращённая TIME-проба не дала положительного контроля и не засчитана.
- Повтор со штатным daily RRULE, BYDAY всех дней и BYSECOND=0: контрольный
  сценарий выполнился, отменённый — нет. Cancel оставил is_active=true, то есть
  не заменил выключение автосрабатывания.
- После обеих проверок созданные cloud ID и HA registry entries удалены;
  в аккаунте снова 12 сценариев, домашний режим совпадает с исходным.

Финальная сборка с отдельным переводом 409 установлена; все 219 SHA-256
совпадают с исходниками. Backup предыдущей тестовой сборки:
`/config/.sberhome-deploy/20261104T130948Z/sberhome-before.tar.gz`.
Повторный вызов cancel во время выполнения показал новую понятную подсказку,
затем stop прервал тест и cleanup удалил оба cloud ID и шесть HA-сущностей.
Снова 12 сценариев; polling и WS работают, домашний режим не менялся.
