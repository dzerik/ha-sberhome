# Design

Согласованный bounded scope описан в
[исследовании №62](../../../research/2026-11-04-issue-62-entity-lifecycle.md).
Используются существующие coordinator callbacks и сущности, без нового API.

1. Общий service identifier groups защищается так же, как scenarios/indicator.
2. Switch-платформа регистрирует listener, хранит уже созданные ID по типу
   сущности и добавляет новые после успешных обновлений. Unload снимает listener.
3. Имена следуют текущему инвентарю, а HA registry сохраняет custom name/ID.
   Переводные имена обновляются с учётом кэша HA, проверяются на пяти языках.
4. Удаление cloud объекта не удаляет пользовательскую запись: сущность
   unavailable, возврат same ID восстанавливает её без дублирования.
5. Home inventory обновляется после успешного получения списка; неуспешный
   запрос не очищает последний подтверждённый список. Состояния at_home
   перечитываются существующим путём.
6. Для групп требуется актуальная GROUP и непустой состав с онлайн-участником.
   Push любого участника уведомляет агрегат, сохраняя фильтрацию device data.

Обязательная проверка — TDD на реальном тестовом HA с MockTransport: prune,
discovery, rename, removal/return/type change, registry overrides, disabled
entities, excluded member push, ошибки inventory и unload/reload.
Публикация выполняется после завершения реализации и её проверки; результаты
CI/беты и ссылка на архив добавляются в GitHub issue. Архив описывает
проверенный код, факт релиза не отмечается до его публикации.
